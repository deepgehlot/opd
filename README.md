# OPD Brief — Vercel edition

This is the edited version of your uploaded OPD project. It preserves the Hindi/English patient portal, staff and doctor dashboards, registration, demo OTP, active visits, vitals, doctor-to-staff notes, review queues, camera/voice intake and source-linked summaries.

Start with **DEPLOY_VERCEL.md** for exact setup. You need a MongoDB Atlas connection string and an OpenAI API key. A Blob account is not required: files are stored privately in MongoDB GridFS.

## Local run

Install Node.js 24. From this folder:

```bash
npm ci
```

Copy `.env.example` to `.env`, fill `MONGODB_URI` and `OPENAI_API_KEY`, then:

```bash
npm start
```

Open http://localhost:3000. The same MongoDB-backed code runs locally and on Vercel. No local JSON database or `/tmp` data directory is used. The application requires MongoDB even locally. OpenAI must be configured for extraction/transcription; the normal application has no mock AI mode.

## Vercel changes

- Node function entry point and explicit API rewrite, preserving document query parameters.
- Persistent users, patient records, visits, activity log, OTP challenges and sessions in MongoDB. No in-memory-only authentication.
- Private GridFS file storage. Records/files remain after server cold starts and redeployments.
- Files/audio uploaded in 768 KiB chunks. Each request stays below Vercel's request body limit while retaining the 10 MiB per-file cap.
- File originals stream through an authenticated endpoint. Binary retrieval/chunk assembly was checked against a real MongoDB replica set.
- Transactions, revision checks and database-backed visit locks prevent conflicting updates from silently overwriting one another.
- One active visit per patient; completed visits remain locked, including their vital measurements.
- Failed extraction retains the original source and supports retry. Unfinished upload chunks expire after one hour. Persistent document originals do not auto-expire.
- Local Devanagari fonts and a style policy compatible with your uploaded layouts.
- Missing medicine/allergy data says unknown. Vitals remain recorded measurements; BMI is explicitly calculated from entered height/weight, without automatic diagnostic classification.

The free Atlas storage allowance also contains uploaded files, indexes and logs. Use synthetic records for this demo. This is a fixed-OTP hackathon application, not a production hospital deployment. No diagnosis or treatment is generated by AI; human doctor notes are preserved.

## Structure

- `api/index.mjs`: Vercel function wrapper.
- `server.mjs`: shared routes, role checks and business flow.
- `storage.mjs`: MongoDB collections, transactions, locks, chunks and GridFS.
- `ai.mjs`: OpenAI extraction/transcription and source validation.
- `public/`: your bilingual portal interface and bundled fonts.
- `demo-documents/`: clearly labelled synthetic report fixture.

## Troubleshooting

- `Database unavailable`: check Atlas database-user credentials, network access and connection-string password encoding.
- `Add MONGODB_URI`: set the variable in Vercel for the intended environment, then redeploy.
- `OpenAI API key missing`: set `OPENAI_API_KEY` and redeploy. API billing/model access are separate from a ChatGPT subscription.
- Upload interrupted: start the upload again. Individual chunk requests retry up to three times and are idempotent.
- Extraction failed: the source is saved; use Retry after fixing the provider configuration.
- A record is being processed: another operation holds its visit lock. Retry after it completes; abandoned locks expire after three minutes.
- A record changed: refresh and retry. No stale overwrite is accepted.
- Microphone/camera unavailable: allow browser permissions and use HTTPS (or localhost). Typed intake remains available.
- Stale UI after deployment: hard-refresh the page so its upload client matches the server version.

Do not upload `.env`, `.git`, `node_modules`, local logs or actual patient records to the source repository.
